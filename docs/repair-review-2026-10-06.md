# 溯页：现有项目审查与修复记录

日期：2026-10-06。范围：现有项目的代码审查、数据留存与错误处理修复、生产构建、源码发布。

## 本轮优先级

重度阅读会不断切换段落、工具、文献与对话。最先需要保证的是读者写下的内容能留存、编辑状态与列表一致，以及翻译能追溯到正确原文。本轮优先修复这些路径。

## 已处理的问题

| 不足 | 原因 | 修改 |
| --- | --- | --- |
| 切换段落或对话后草稿同步可能丢失 | 每个组件只有一个待同步槽位；旧请求失败与新编辑竞争；组件卸载后停止重试 | 按草稿键维护独立队列；同一键串行同步；成功只移除对应版本；卸载后继续同步；超时后重试 |
| 空字符串等草稿不能恢复 | 用真值判断 value 是否存在 | 检查属性是否存在，允许空字符串、false 和 0；校验保存时间 |
| 连续的函数式更新使用旧值 | 更新函数依赖组件渲染时的状态 | 使用最新引用计算下一值，并为同一草稿生成递增保存时间 |
| 编辑笔记后关闭窗口丢失输入 | 编辑字段只有组件内状态 | 接入统一草稿机制；按笔记 ID 保存；以笔记更新时间校验基线，避免旧草稿覆盖后来保存的版本 |
| 长 AI 收藏草稿无法同步 | 草稿限制比笔记内容限制小 | 扩大草稿信封上限至 200,000 字符；保留正文和标签字段的原有长度约束 |
| 译文修改依赖失焦保存 | 输入时没有可靠的草稿副本 | 每次编辑保留草稿，600ms 防抖写入译文缓存；恢复后补同步；显示同步错误；复制和收藏均使用修改后的内容 |
| 译文可能复用不匹配的语境 | 缓存未区分论文 ID、页码、完整上下文与协议 | 使用 v3 缓存键，包含论文、解析版本、目标语、标题、章节、邻文、术语和供应商配置 |
| 缓存升级可能隐藏读者校对内容 | 旧缓存键和新缓存键不同 | 仅在论文、页码、解析版本和引用原文一致时迁移旧版人工校对译文，并标明它来自旧版本 |
| 原文未匹配时翻译邻文取错 | -1 下标产生错误切片，误取第一块正文 | 未匹配时不使用无效索引；仅使用可定位的邻文，并限制语境长度 |
| 切换段落后 AI 翻译仍在后台执行 | 前端取消没有传到供应商 | 服务端监听连接关闭，把 AbortSignal 传给供应商；被取消后不保存生成结果 |
| 较晚到达的旧编辑覆盖新译文 | 缓存写入没有时间顺序校验 | 使用原子条件写入，拒绝旧版本并返回 409；保留本地草稿用于核对 |
| 收藏失败不反馈或重复提交 | 回调吞掉异常，没有保存状态 | 收藏操作显示进行中，禁用重复提交，捕获并显示失败 |
| 笔记列表的本地覆盖缓存一直保留旧内容 | 编辑结果同时存于父状态与组件内部映射 | 去掉重复映射，以父级更新后的记录作为列表来源 |
| 按论文标题搜索可能漏掉笔记或术语 | 原始记录未必带 paperTitle | 从文献集合补充标题，并纳入笔记和术语搜索 |
| 删除笔记和术语容易误操作 | 直接调用 DELETE，失败没有界面反馈 | 使用现有统一确认弹窗；成功后同步文献内和全局列表；失败显示错误 |
| 错误代理返回 HTML 后页面表现为空数据 | JSON 解析失败时返回空对象 | 成功响应不是有效 JSON 时显示明确配置错误；HTTP 错误保留状态码 |
| 发布可能误包含本机资料 | 忽略规则按少量已知文件列举 | 忽略整个 data 目录、环境配置及 Python 缓存；保留 .env.example |

## 实现分工与维护约定

- `usePersistentDraft.ts`：本地恢复、按键排队、同步与重试。编辑页面复用此机制，不各自实现草稿计时器。
- `AssistantTranslatePanel.tsx`：原文选择、翻译交互、校对草稿、复制和收藏。
- `assistantRoutes.ts`：来源校验、语境选择、缓存身份、请求取消和译文版本写入。
- `NoteEditor.tsx`：笔记字段编辑和草稿基线。正式保存由父级更新列表。
- `api.ts`：JSON 契约校验、状态码错误和只读请求有限重试。写入操作不在此层自动重发。
- `workspaceRoutes.ts`：草稿输入校验与版本写入。

草稿与正式笔记分开保存。关闭编辑会保留草稿，点击“保存修改”才更新正式笔记。后端返回 400、404 或 409 时停止无效重试，并保留浏览器副本；网络或服务暂时不可用时继续重试。清除浏览器存储会移除未同步的本地副本，因此本地提示不等同于服务端备份。

## 构建与检查边界

- `npm run build`：前端 TypeScript、后端 TypeScript、Vite 生产构建和解析资源复制通过。
- 本輪使用代码审查定位问题，没有运行端到端或自动化测试，也没有修改用户论文、笔记、供应商配置等数据。
- 没有调用真实供应商评估回答或翻译质量；取消请求能否立即停止服务商计费取决于服务商实现。
- 本轮没有重新打包 Windows 安装程序。桌面源码已纳入提交，但新版安装包需另外执行构建流程。
- Vite 仍提示主包超过 500kB，需要后续按页面与功能拆包。
- 扫描 PDF、复杂多栏版面、数学公式和表格结构仍无法保证全部准确；原 PDF、解析质量提示与人工校对入口应继续保留。

## 下一轮建议

1. 按文献库、阅读工作区、笔记页和 AI 工具拆分前端加载，减少初次打开成本。
2. 对草稿与文献建立清理策略：保存后的过期草稿、已删除文献的本地副本、存储容量提示。
3. 增加显式版本冲突处理界面，可比较本地修改与服务端记录；当前时间顺序机制不能自动合并多人编辑。
4. 提供删除撤销或回收站，并与正式备份和恢复流程衔接。
5. 建立经过人工标注的不同出版社 PDF 样本集，分别衡量阅读顺序、标题、图表和公式识别，避免用少量成功样本推断所有论文。
6. 获得可用供应商后，在用户授权下补做真实 AI 的来源引用、翻译术语一致性、请求停止与回答收藏检查。

GitHub Pages 只承载前端。代码推送到 main 会触发已有发布工作流；线上 API 地址与服务运行状态仍是发布成功的必要条件。

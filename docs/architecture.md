# 本地论文学习架构

## 运行与职责

React 负责交互；浏览器与 Electron 共用界面。Node API 管理文献、任务、学习记录及 AI 调用。桌面主进程只启动独立 utilityProcess API 和隔离的浏览器窗口；PDF 重建在 worker thread 中运行，PyMuPDF 在独立本地进程中运行。渲染进程没有 Node 权限。

`main.tsx` 负责工作区编排；`documentText.tsx` 负责层级、样式和数字字体；`ReaderToolbar` 负责阅读设置；`ReaderNavigation` 管理检索结果。PDF 文档缓存与渲染分开，闲置文档数量有上限。其他功能由 assistant、notes、study 模块维护。

## 来源契约

SourceAnchor 包含 paperId、fileHash、extractionRevision、pageIndex、可选 blockId、quote 的 exact/prefix/suffix，以及原始未旋转页面的归一化矩形。按稳定块 ID 和完整引文定位；无法唯一定位时打开原始页，不默默跳到相似段落。服务端先验证完整引文，必要时直接核对原 PDF 文字层，再调用 AI 或保存标注。

重新解析保留 PDF 文件/hash、创建新 revision 并归档提取快照；校对按原文字串重新匹配；未匹配项目提示。旧锚点保留原版本/引文以供核对。当前没有归档版本可视化管理页。

## 存储与一致性

SQLite WAL，FULL 同步与短事务。各类记录分表，以 JSON payload 保持旧数据契约；变更按读取快照作三方合并，独立字段及不同 ID 的新增可共存。冲突返回 409，不覆盖已删除记录。草稿和阅读会话的时间戳比较与写入在同一事务中完成。

FTS5 按原文块索引；更改精读文本后更新索引。日常阶段状态或分组变动不会重建全文索引。旧 JSON 仅为迁移输入，迁移前复制备份，记录数量核对失败则停止。浏览器本地草稿立即保存，服务端延迟同步/在线后重试。

## 后台解析

上传异步模式返回 job；队列串行执行以限制本机资源。worker 进度保存在数据库，网页刷新可恢复轮询。失败不会覆盖旧文献；重启会将未结束任务标记为中断。超时、启动失败、提前退出都有终态。原文件不自动修改。

优先 PyMuPDF 字体与几何数据，失败回退 PDF.js。章节与版面采用现有规则重建；低文字页尝试英文 OCR，缺少 Tesseract 语言数据时给出明确提示。图表使用原页裁切，读者可修正范围；复杂表格没有自动结构化单元格保证。

## AI 与证据

providers 负责协议、鉴权、错误和增量输出；prompts 负责学习任务规则。全文问题采用 FTS5 与关键词/章节加权，按问题类型分配出处；28 处、42,000 字符上限，不能视为全文每段都已阅读。发送最近最多 30 条消息并限制上下文字符预算。

回答使用服务器生成的来源 ID；返回的引用仅映射已检索来源，未知 ID 标为未核实。引用有效不等于结论自动证实。NDJSON 事件 start/delta/done/error；断开连接触发 AbortSignal，已收到部分文本保存到同一消息 ID。对话删除不会被晚到的回答重新创建。

翻译缓存包括文件、解析版本、原文、目标语言、相关术语、供应商/模型/端点和提示版本。只翻译选中原文，同时提供章节和前后段落。编辑后保留 originalAnswer；重新生成需要读者主动操作。

## 学习与界面

六阶段主线以章节和关键词初选出处；读者主动确认理解后计入进度。方法卡与结果/作者解释分别提供原文线索。笔记按论文分组，先显示摘要，每组分批展示，全文搜索包含标签和 AI 回答，可导出 Markdown。

## 可选扩展

Docling 等模型解析应实现同一提取契约，保留各引擎版本；不在 GET 论文时隐式切换。先用真实版式建立人工核对样本，再决定是否引入模型和嵌入。表格结构、跨文献问答、归档版本管理、OCR 语言模型打包、来源语义校验和云同步尚未实现。
